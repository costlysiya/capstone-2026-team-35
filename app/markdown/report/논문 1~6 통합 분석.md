# 선행연구 분석 및 이론적 근거 도출 리포트: 논문 1~6 통합본

> 본 문서는 소생 앱 졸업과제의 최종보고서에 활용할 수 있도록 제공된 논문 6편을 동일한 기준으로 분석한 통합본이다. 각 논문의 **원문에서 확인한 주장·수치**와, 이를 소생 앱에 연결한 **프로젝트 해석**을 구분하였다. 논문이 직접 검증하지 않은 한국어 스크린샷, 본 프로젝트의 성능, 개인정보 마스킹 효과는 해당 논문의 결과로 서술하지 않는다.

## 공통 인용 원칙

- 선행연구의 수치는 해당 논문의 데이터·장비·과업에서만 성립한다. 소생 앱 성능의 증거로 바꾸어 쓰지 않는다.
- 프로젝트의 Field-level Precision/Recall/F1, Regex·LLM 지연시간·비용은 [`ondevice_vs_llm_comparison_report_v2.md`](ondevice_vs_llm_comparison_report_v2.md)의 조건을 명시하여 **자체 실험 결과**로 제시한다.
- 개인정보 마스킹·암호화·SQLite JSON 저장·서버 캐시는 별도의 프로젝트 설계와 구현 근거이다. 관련 논문이 해당 요소를 직접 평가하지 않은 경우, ‘설계 참고’로만 표현한다.

## [논문 1] 개인정보 보호형 LLM 기반 실시간 근로계약서 분석 및 가이드 시스템

### 1. 서지정보

| 항목 | 내용 |
|---|---|
| 저자 | 이종한, 박성재, 이채은, 권아현, 김민재, 신현석, 황연우, 서왕덕 |
| 학회/저널 | 2026 한국정보기술학회 하계 종합학술대회 논문집 |
| 발표연도 | 2026 |
| DOI 또는 공식 링크 | 원문에 DOI·공식 논문 링크 미기재; 제공 PDF 기준 |
| 논문 유형 | 국내 학술대회 시스템 제안·구현 논문 |

### 2. 연구 목적 및 문제 정의

근로계약서 원문을 외부 서버로 전송하는 AI 분석 서비스는 개인정보 유출 위험이 있고, 일반 근로자는 계약서의 위험 조항을 스스로 판단하기 어렵다는 문제를 다룬다(Ⅰ절, p. 2). 저자들은 스마트폰 촬영 계약서를 클라이언트에서 OCR·비식별화한 뒤, 마스킹된 텍스트만 LLM에 보내 위험 조항과 대응 가이드를 산출하는 시스템을 제안한다.

### 3. 핵심 내용

- **방법:** Google ML Kit OCR로 블록·라인·단어와 위치·신뢰도 등을 얻고, 문단·문장·단어의 계층 구조로 재구성한다(Ⅲ절 및 4.1절, p. 2-3). 고유명사 문장에 KoELECTRA NER를 적용하고 정규식으로 보완해 성명·주소·연락처·주민등록번호 등을 라벨로 치환한다(4.2절, p. 3).
- **LLM·저장 형식:** 마스킹 텍스트를 JSON으로 서버에 보내며, Groq API의 Llama 3.3이 문장별 위험도를 state 0~3으로 판단한다. 출력은 `block_id`, `sentence_id`, `state`, `reason`, `law`, `action`의 JSON으로 제한한다(Ⅲ절, p. 3; 4.3절, p. 4).
- **결과와 한계:** 논문은 실증적 Precision/Recall/F1·지연시간·비용 수치를 보고하지 않는다. 결론에서 수기 정보 OCR 한계, 법률 도메인 NER 오인식, 정량 성능지표 부재를 후속 과제로 명시한다(Ⅴ절, p. 4).

### 4. 우리 졸업과제와의 연관성

| 관점 | 판단 | 원문 근거와 프로젝트 해석 |
|---|---|---|
| OCR / 이미지 기반 정보 추출 | 높음 | **논문:** 모바일 촬영 이미지에 ML Kit OCR을 적용한다. **해석:** 소생 앱의 스크린샷 OCR 전처리와 직접적으로 연결된다. |
| LLM 비정형 데이터 구조화 | 높음 | **논문:** 마스킹 텍스트를 LLM으로 분석하고 고정 JSON 결과를 반환한다. **해석:** 소생 앱의 structured output 설계 참고가 된다. |
| 온디바이스-클라우드 역할 분리 | 매우 높음 | **논문:** 클라이언트 OCR·비식별화, 서버 LLM 분석으로 분리한다. |
| Precision / Recall / F1 | 해당 없음 | 정량 지표가 보고되지 않았다. |
| 처리 속도 및 비용 | 해당 없음 | ‘실시간’을 지향하나 수치 실험은 없다. |
| 구조화 저장 | 부분적 연관 | JSON 전송·응답 구조는 제시하나 DB 스키마·저장 성능은 다루지 않는다. |
| 모바일/온디바이스 | 높음 | 모바일 촬영 및 클라이언트 OCR·NER 처리를 명시한다. |
| 개인정보·보안 | 매우 높음 | 서버 전송 전 NER·정규식 기반 라벨 치환을 핵심으로 제안한다. 단, 암호화나 침투 보안 평가는 없다. |
| 확장 가능한 아키텍처 | 낮음 | 확장성 실험은 없다. |

### 5. 최종보고서에서 사용할 수 있는 핵심 근거

1. **논문의 주장:** 클라이언트에서 OCR 후 개인식별정보를 마스킹하고, 마스킹 텍스트만 LLM에 전달하는 분리형 파이프라인을 제안한다. **원문 위치:** 초록, p. 1; Ⅲ절·4.2절, p. 2-3. **활용:** 서버 전송 이전의 로컬 민감정보 전처리 설계 근거.
2. **논문의 주장:** LLM 출력 형식을 필수 필드를 포함하는 JSON으로 제한하고 서버에서 파싱·범위 검증을 수행한다. **원문 위치:** 4.3절, p. 4. **활용:** 비정형 OCR 텍스트를 검증 가능한 구조화 데이터로 변환하는 설계 근거.
3. **주의 근거:** NER 도메인 오인식과 정량 평가 부재가 한계로 제시되었다. **원문 위치:** Ⅴ절, p. 4. **활용:** 본 프로젝트에서 사용자 수정·확정 단계와 별도 성능평가가 필요한 이유.

### 6. 최종보고서용 서술문

이종한 등(2026)은 모바일에서 촬영한 근로계약서를 클라이언트에서 OCR 처리한 뒤, NER 및 정규식 기반 비식별화를 수행하고 마스킹된 텍스트만 서버 LLM으로 전달하는 처리 구조를 제안하였다[이종한 등, 2026]. 또한 LLM 결과를 정해진 JSON 필드로 제한하고 유효성을 확인하도록 구성하여, 비정형 문서 분석 결과를 후속 시스템에서 활용 가능한 형태로 만들고자 하였다.

본 프로젝트도 스크린샷의 OCR 결과를 처리하므로, 서버 전송 전 단말에서 민감정보를 처리하고 비정형 결과를 구조화된 형식으로 다루는 설계 원칙을 참고하였다. 다만 이 논문은 근로계약서 도메인이고 정량 성능지표를 제시하지 않았으므로, 소생 앱의 개인정보 보호 효과와 추출 정확도는 본 프로젝트의 자체 설계·평가 결과로 분리하여 제시한다.

## [논문 2] On-device LLM모델의 반응성 향상을 위한 동적 배치 최적화 기술

### 1. 서지정보

| 항목 | 내용 |
|---|---|
| 저자 | 정휘수, 이지훈, 주성진, 이길호 |
| 학회/저널 | 2024 한국소프트웨어종합학술대회 논문집 |
| 발표연도 | 2024 |
| DOI 또는 공식 링크 | 원문에 DOI·공식 논문 링크 미기재; 제공 PDF 기준 |
| 논문 유형 | 국내 학술대회 논문 |

### 2. 연구 목적 및 문제 정의

임베디드 환경에서 LLM을 실행할 때 고정 배치 크기는 입력 길이 변화와 메모리 제약을 반영하지 못해 GPU 활용률 저하 및 OOM(Out-of-Memory)을 유발할 수 있다(1절, p. 1). 저자들은 가용 메모리, 입력·출력 토큰 수, 배치 내 패딩을 고려하는 동적 배치 알고리즘으로 반응성을 개선하고자 했다.

### 3. 핵심 내용

- **방법:** First-Fit 빈 패킹으로 토큰을 배치에 묶고, 토큰 길이 차이와 패딩 오버헤드를 줄이도록 배치 조합을 재분할한다(3-4절, p. 2-3).
- **환경:** Jetson AGX Orin 32 GB에서 Phi-3-medium-4k-instruct(14B), OpenBookQA 가공 데이터, PyTorch 2.3.0을 사용했다(5.1절, p. 3).
- **결과:** 기존 PyTorch는 배치 크기 8에서 OOM이 발생했으나, 제안 방법은 OOM을 피하면서 Vanilla batch 4 대비 1.9배 빠른 지연시간을 보였다(5.2절, p. 3).

### 4. 우리 졸업과제와의 연관성

| 관점 | 판단 | 원문 근거와 프로젝트 해석 |
|---|---|---|
| OCR / 이미지 기반 추출 | 해당 없음 | OCR·이미지를 다루지 않는다. |
| LLM 비정형 데이터 구조화 | 낮음 | LLM 추론 운영을 다루지만 구조화 추출은 평가하지 않는다. |
| 온디바이스-클라우드 역할 분리 | 낮음 | 온디바이스 LLM 추론 자체가 대상이며 클라우드 분할은 다루지 않는다. |
| Precision / Recall / F1 | 해당 없음 | 과업 품질지표를 보고하지 않는다. |
| 처리 속도 및 비용 | 높음 | 가변 배치·메모리·패딩 관리와 지연시간 1.9배 개선을 실험했다. 비용은 다루지 않는다. |
| 구조화 저장 | 해당 없음 | 저장 구조는 다루지 않는다. |
| 모바일/온디바이스 | 보통 | Jetson 임베디드 보드 실험이다. 스마트폰 실험은 아니다. |
| 개인정보·보안 | 해당 없음 | 개인정보 보호를 실험하지 않는다. |
| 확장 가능한 아키텍처 | 부분적 연관 | 요청 길이 변화와 자원 제약에 대응하는 운영 전략이라는 점에서 참고 가능하다. |

### 5. 최종보고서에서 사용할 수 있는 핵심 근거

1. **논문의 주장:** 고정 배치 크기는 입력 길이 변동 환경에서 비효율과 OOM을 유발할 수 있다. **원문 위치:** 1-2절, p. 1-2. **활용:** 다중 이미지의 LLM 요청에 동시성 제어가 필요한 문제 배경.
2. **논문의 주장:** 메모리와 패딩을 고려한 동적 배치가 OOM을 피하면서 Vanilla batch 4 대비 1.9배 빠른 지연시간을 보였다. **원문 위치:** 5.2절, p. 3. **활용:** 처리량 관리가 지연시간·안정성에 영향을 준다는 근거. 소생 앱의 Semaphore=3 효과 수치로 바꾸어 인용하지 않는다.

### 6. 최종보고서용 서술문

정휘수 등(2024)은 임베디드 LLM 추론에서 고정 배치 크기가 입력 길이 차이와 제한된 메모리를 충분히 반영하지 못해 OOM과 불필요한 패딩 연산을 유발할 수 있다고 보았다[정휘수 등, 2024]. 이에 가용 메모리와 토큰 길이에 따라 배치를 구성하는 방법을 제안하였으며, Jetson AGX Orin 환경에서 기존 방식보다 낮은 지연시간과 OOM 회피 가능성을 보고하였다.

본 프로젝트에서는 이 논문의 동적 배치 알고리즘을 그대로 구현하지는 않았다. 다만 다수 이미지의 LLM 분석 요청이 동시에 발생할 때 처리량과 외부 API 요청 수를 제어해야 한다는 문제의식을 참고하여 서버 측 동시성 제한을 적용하였다. 이에 따른 실제 일괄 처리 성능은 프로젝트 자체 벤치마크로 제시한다.

## [논문 3] ScreenSeg: On-Device Screenshot Layout Analysis

### 1. 서지정보

| 항목 | 내용 |
|---|---|
| 저자 | Manoj Goyal, Rachit S. Munjal, Sukumar Moharana, Deepak Garg, Debi Prasanna Mohanty, Siva Prasad Thota |
| 학회/저널 | arXiv |
| 발표연도 | 2021 (v2: 2021-04-21) |
| DOI 또는 공식 링크 | https://arxiv.org/abs/2104.08052 |
| 논문 유형 | arXiv 사전공개본(preprint) |

### 2. 연구 목적 및 문제 정의

자원이 제한된 모바일 기기에서 스크린샷·문서 이미지의 레이아웃을 이해하고, 텍스트·이미지·아이콘·격자 블록을 분할하는 문제를 다룬다(초록 및 Ⅰ절, p. 1). 저자들은 화면 구성요소 분할과 이미지 처리 기법을 결합해 온디바이스 레이아웃 분석을 수행하고자 했다.

### 3. 핵심 내용

- **방법:** 계층적 엔터티 분할과 이미지 처리를 결합하고, 가중 NMS 및 grid block 검출로 블록 경계 보정과 계층 구조 생성을 수행한다(Ⅲ절, p. 2-7).
- **데이터·환경:** 합성 텍스트·스크린샷을 포함한 25,000장의 512×512 이미지로 학습하고 2,500장을 검증·시험에 사용했다(p. 5). 평가는 3명의 주석자가 라벨링한 스크린샷·scene text·wallpaper 750장에 대해 수행했다(Ⅳ절, p. 7).
- **결과:** Galaxy S10(Exynos 9820)에서 1080p×2240p 스크린샷당 평균 200 ms, RAM 60 MB, ROM 3 MB를 보고했다. 전체 Precision 0.95, Recall 0.93, HMean 0.94였으며, 텍스트 블록은 Precision 0.97, Recall 0.93, HMean 0.95였다(표 I, p. 8).
- **한계:** 이미지와 텍스트가 명확한 경계 없이 결합된 경우 등 실패 사례를 보였고, 표 추출·블록 의미 기반 순위화는 향후 과제로 제시했다(그림 7 및 Ⅴ절, p. 8).

### 4. 우리 졸업과제와의 연관성

| 관점 | 판단 | 원문 근거와 프로젝트 해석 |
|---|---|---|
| OCR / 이미지 기반 추출 | 높음 | 스크린샷에서 텍스트 블록을 포함한 레이아웃 구성요소를 검출한다. 다만 OCR 문자 인식·필드 추출을 평가하지는 않는다. |
| LLM 비정형 데이터 구조화 | 해당 없음 | LLM을 사용하지 않는다. |
| 온디바이스-클라우드 역할 분리 | 부분적 연관 | 온디바이스 화면 분석은 검증했으나 클라우드 처리와의 분할은 다루지 않는다. |
| Precision / Recall / F1 | 높음 | 블록 분할의 Precision·Recall·HMean을 제시한다. 소생 앱 필드 추출 P/R/F1과는 다른 과업이다. |
| 처리 속도 및 비용 | 높음 | Galaxy S10에서 200 ms, 메모리·ROM 사용량을 보고한다. 비용은 미보고. |
| 구조화 저장 | 해당 없음 | DB 저장 구조를 다루지 않는다. |
| 모바일/온디바이스 | 매우 높음 | 모바일 기기에서 실제 측정한 레이아웃 분석 연구이다. |
| 개인정보·보안 | 해당 없음 | 보안·비식별화 평가가 없다. |
| 확장 가능한 아키텍처 | 부분적 연관 | 추가 블록 유형·표 추출을 향후 과제로 언급한다. |

### 5. 최종보고서에서 사용할 수 있는 핵심 근거

1. **논문의 주장:** 스크린샷의 텍스트·이미지·아이콘·grid 블록을 계층적으로 분석하는 경량 온디바이스 파이프라인을 제안한다. **원문 위치:** 초록, p. 1; Ⅲ절, p. 2-7. **활용:** 스크린샷에서 OCR 전후에 이미지 구성 정보를 활용하는 필요성.
2. **논문의 주장:** 텍스트 블록 검출은 Precision 0.97, Recall 0.93, HMean 0.95이며 전체 파이프라인은 Galaxy S10에서 평균 200 ms였다. **원문 위치:** 표 I 및 Ⅳ-Ⅴ절, p. 7-8. **활용:** 모바일 이미지 분석은 정확도와 지연시간을 함께 보고해야 한다는 평가 관점.
3. **논문의 주장:** 경계가 불명확한 텍스트·이미지 결합 블록은 실패 사례이며, 표 추출은 향후 과제다. **원문 위치:** 그림 7 및 Ⅴ절, p. 8. **활용:** 복합 레이아웃 스크린샷에 대한 자체 오류 분석 필요성.

### 6. 최종보고서용 서술문

Goyal et al.(2021)은 모바일 기기에서 스크린샷의 텍스트, 이미지, 아이콘 및 격자 블록을 계층적으로 분할하는 ScreenSeg를 제안하였다[Goyal et al., 2021]. 해당 연구는 Galaxy S10에서 평균 200 ms의 처리시간과 블록 분할 Precision 0.95, Recall 0.93을 보고하여, 화면 이미지 분석에서 정확도뿐 아니라 단말 자원과 지연시간을 함께 고려할 필요성을 보여준다.

본 프로젝트는 ScreenSeg와 동일한 레이아웃 분할 모델을 적용하지 않았으나, 스크린샷이 텍스트 외에도 시각적 구성 정보를 가진 입력이라는 점과 온디바이스 이미지 분석의 측정 관점을 참고하였다. 다만 ScreenSeg의 성능은 블록 검출 기준이므로, 이를 소생 앱의 OCR 문자 인식 또는 필드 추출 성능으로 해석하지 않았다.

## [논문 4] LLM과 생성형 AI 기반 청소년 비속어 예방 애플리케이션 설계 및 구현

### 1. 서지정보

| 항목 | 내용 |
|---|---|
| 저자 | 김호준, 김현동, 손서희, 배성욱, 옥지원, 이세종 |
| 학회/저널 | *한국컴퓨터정보학회논문지* (Journal of The Korea Society of Computer and Information), 30(3), 1-8 |
| 발표연도 | 2025 |
| DOI 또는 공식 링크 | https://doi.org/10.9708/jksci.2025.30.03.001 |
| 논문 유형 | KCI 등재 학술지의 시스템 설계·구현 논문 |

### 2. 연구 목적 및 문제 정의

청소년의 비속어·사이버폭력 문제에서 단순 키워드 필터는 문맥을 반영하지 못하고, 부모 모니터링은 자녀의 사생활을 침해할 수 있다는 문제를 다룬다(Ⅰ절, p. 2-3). 저자들은 키패드의 온디바이스 분류, 선택적 GPT-4o 문장 대치, RAG 기반 주간 리포트를 결합한 ‘바른말ㅆ.미’ 서비스를 설계·구현했다.

### 3. 핵심 내용

- **방법:** 입력 중인 문장을 KoSimCSE-BERT-multitask(110M 파라미터)로 비윤리·비속어·감정을 분류하며, 임계값을 넘는 경우에만 GPT-4o로 문장 대치를 요청한다(Ⅲ절, p. 4). 주간 리포트는 누적 입력을 RAG로 검색·생성한다.
- **데이터·평가:** AI Hub의 한국어 비윤리 텍스트 453,320문장과 KOTE 기반 KcELECTRA 감정 라벨을 사용했다. TitanX 8대, PyTorch, epoch 3, learning rate 0.001, batch 32 조건이며 F1을 평가 지표로 사용했다(Ⅳ.1절, p. 5; 표 3).
- **결과:** 표 4는 도덕성 단독과 감정 결합 학습의 클래스별 F1을 제시한다. 예를 들어 immoral은 0.71/0.71, HATE는 0.05/0.11, CENSURE는 0.51/0.25이다. 표 5에서는 중의적 문장의 비윤리 점수가 감정 결합 시 낮아진 사례를 제시한다(p. 5). LLM·RAG 리포트의 정확도·비용·지연시간은 정량 보고되지 않았다.

### 4. 우리 졸업과제와의 연관성

| 관점 | 판단 | 원문 근거와 프로젝트 해석 |
|---|---|---|
| OCR / 이미지 기반 추출 | 해당 없음 | 텍스트 키패드 입력을 다룬다. |
| LLM 비정형 데이터 구조화 | 보통 | GPT-4o 문장 대치 및 RAG 리포트를 사용한다. JSON 필드 추출은 다루지 않는다. |
| 온디바이스-클라우드 역할 분리 | 높음 | 실시간 분류는 단말 모델, 임계값 초과 문장은 GPT-4o, 누적 데이터는 RAG 리포트로 역할을 나눈다. |
| Precision / Recall / F1 | 부분적 연관 | 분류 F1을 제시하나 소생 앱의 필드 추출 지표와 과업이 다르다. |
| 처리 속도 및 비용 | 낮음 | 선택 호출의 설계는 제시하지만 수치는 없다. |
| 구조화 저장 | 부분적 연관 | Text·Report 등 5개 테이블의 ERD와 저장 흐름을 제시한다(그림 2, p. 4). |

| 확장 가능한 아키텍처 | 부분적 연관 | 앱·키패드·백엔드 endpoint 구분과 DB 엔터티를 제시한다. 확장성 실험은 없다. |

### 5. 최종보고서에서 사용할 수 있는 핵심 근거

1. **논문의 주장:** 온디바이스 분류가 임계값을 넘는 경우에만 GPT-4o 문장 대치를 요청한다. **원문 위치:** Ⅲ절 ‘Keypad AI’, p. 4. **활용:** 모든 입력을 LLM에 보내지 않고 후속 처리를 선택적으로 수행하는 설계 원칙.
2. **논문의 주장:** 453,320문장과 감정 라벨을 이용해 KoSimCSE-BERT-multitask를 평가하고 F1을 사용했다. **원문 위치:** Ⅳ.1-2절 및 표 3-5, p. 5. **활용:** 분류 평가에서 F1 및 예외 사례를 함께 제시하는 방법론적 참고.
3. **논문의 주장:** Text·Report·Parent·Child·Friend로 구성된 ERD 및 리포트 생성 endpoint를 제시한다. **원문 위치:** 그림 2, p. 4; 표 6, p. 7. **활용:** 분석 결과 저장과 서비스 기능을 분리하는 시스템 구성의 사례.

### 6. 최종보고서용 서술문

김호준 등(2025)은 실시간 판단이 필요한 입력은 온디바이스 KoSimCSE-BERT-multitask로 처리하고, 임계값을 넘는 문장에 한하여 GPT-4o의 문장 대치를 수행하도록 구성하였다[김호준 등, 2025]. 이와 같이 처리 특성과 호출 필요성에 따라 단말 모델과 LLM의 역할을 분리한 방식은 모바일 AI 서비스에서 응답성과 외부 호출 범위를 함께 고려한 구현 사례이다.

본 프로젝트도 정형 패턴과 1차 분류는 단말에서 우선 처리하고, 문맥 해석이 필요한 비정형 필드는 선택적으로 LLM 구조화 단계에서 다루도록 설계하였다. 다만 청소년 비속어 분류의 F1과 소생 앱의 OCR 필드 추출 성능은 과업이 다르므로, 각각의 결과를 별도 평가로 제시한다.

### 2. 연구 목적 및 문제 정의

스마트폰에 축적된 문서는 파일명·메타데이터 또는 텍스트만으로 관리하기 어렵고, 개인 문서를 서버로 전송하면 프라이버시와 지연시간 문제가 발생할 수 있다는 문제를 제기한다(1절, p. 1). 저자들은 OCR 텍스트와 문서 이미지의 시각 특징을 결합한 경량 다중모달 모델로 문서 분류를 단말에서 수행하고자 했다.

### 3. 핵심 내용

- **방법:** PDF 첫 페이지를 이미지로 렌더링하고 Google ML Kit로 OCR 텍스트를 추출한다. 텍스트는 TF-IDF와 Truncated SVD, 이미지는 MobileNet으로 특징을 만들며, 두 pre-softmax 특징을 late fusion한다(3-4절, p. 2-4).
- **데이터:** 일반 다중모달 성능은 Food-101(약 10만 이미지, 101개 범주)에서, 실제 문서 분류는 Travel 118, Personal information 100, Receipts 98, Papers/books 102, Misc 94의 약 512건 자체 PDF 데이터에서 평가했다(표 3, p. 3).
- **결과:** 자체 문서에서 텍스트 단독 Top-1 accuracy 59.62%, 시각 단독 71.88%, 결합 84.38%였다(표 4, p. 4). 사후 양자화는 약 0.5%p 정확도 감소, 75% 모델 압축, 약 13 MB 모델을 보였다. 문서당 4.6초 중 OCR이 3.5초였다(4절, p. 4).
- **한계:** 영어·PDF 첫 페이지에 한정되며, 저자들이 자체 데이터셋 크기가 충분하지 않다고 명시했다(5절, p. 4).

### 4. 우리 졸업과제와의 연관성

| 관점 | 판단 | 원문 근거와 프로젝트 해석 |
|---|---|---|

| LLM 비정형 데이터 구조화 | 해당 없음 | LLM을 사용하지 않는다. |

### 5. 최종보고서에서 사용할 수 있는 핵심 근거

1. **논문의 주장:** 자체 문서에서 텍스트·시각 특징 결합 정확도는 84.38%로 단일 특징보다 높았다. **원문 위치:** 표 4, p. 4. **활용:** OCR 텍스트뿐 아니라 이미지 단서를 함께 고려하는 분류 설계 근거.

3. **논문의 주장:** 양자화 후 모델은 약 13 MB, 전체 처리 4.6초 중 OCR 3.5초였다. **원문 위치:** 4절, p. 4. **활용:** 모바일에서는 정확도와 모델 크기·지연시간을 함께 평가해야 한다는 근거.

### 6. 최종보고서용 서술문

Garg, Harichandana, and Kumar(2021)는 OCR 텍스트와 문서 이미지의 시각 특징을 결합하는 온디바이스 문서 분류 파이프라인을 제안하였다[Garg et al., 2021]. 자체 문서 데이터에서 결합 모델은 텍스트 단독 및 시각 단독 모델보다 높은 Top-1 정확도를 보여, 문서 범주 판단에서 두 유형의 특징이 상호보완적으로 활용될 수 있음을 보였다.

본 프로젝트는 이러한 단말 처리 및 다중 단서 활용 원칙을 참고하여 스크린샷의 1차 OCR·분류를 단말에서 수행한다. 그러나 선행연구의 대상은 영어 PDF 첫 페이지와 문서 분류이므로, 해당 결과를 한국어 스크린샷의 필드 추출 성능으로 일반화하지 않고 본 프로젝트의 실험으로 별도 평가하였다.

## [논문 6] REVISE: A Framework for Revising OCRed text in Practical Information Systems with Data Contamination Strategy

### 1. 서지정보

| 항목 | 내용 |
|---|---|
| 저자 | Gyuho Shim, Seongtae Hong, Heuiseok Lim |
| 학회/저널 | arXiv |
| 발표연도 | 2026 (v1 공개일: 2026-04-09) |
| DOI 또는 공식 링크 | https://doi.org/10.48550/arXiv.2604.08115 ; https://arxiv.org/abs/2604.08115 |
| 논문 유형 | arXiv 사전공개본(preprint) |

### 2. 연구 목적 및 문제 정의

OCR 오류는 정보추출·검색·질의응답 등 후속 과업으로 누적 전파될 수 있으나, 기존 Document AI가 구조화된 정보 자산의 보존·관리를 충분히 다루지 못했다는 문제를 제기한다(2.1-2.2절, p. 2-3). 저자들은 문자·단어·문서 구조 수준의 OCR 오류를 보정해 구조적으로 일관된 텍스트를 만드는 REVISE를 제안한다.

### 3. 핵심 내용

- **방법:** 문자 수준 삽입·삭제·치환·전치, 단어 수준 과/과소분절, 열 읽기 순서 오류의 taxonomy를 제시하고(표 1, p. 3), 합성 오류 주입 데이터로 Llama-3.1-1B-Instruct를 학습했다. REVISE meta는 6개 오류를, 보조 모델은 오류별로 다루며 각 학습 데이터는 30,000건이다(3.2-3.3절, p. 4).
- **환경·평가:** EasyOCR을 주로 사용하고, 검색은 VisualMRC·DUDE의 Recall@K, 유사성은 DocVQA·CORD·FUNSD BERTScore, QA는 VisualMRC CIDEr와 CORD F1으로 평가했다(4절, p. 5; 부록 B, p. 11).
- **결과:** REVISE meta의 평균 검색 Recall은 VisualMRC 0.6578→0.6666, DUDE 0.2534→0.2975로 증가했다(표 2, p. 5-6). BERTScore는 세 데이터셋 모두 상승했고(표 3, p. 6), CORD QA F1은 Gemma 0.367→0.372, Llama 0.448→0.450이었다(표 4, p. 6).
- **한계:** 산업 특화 문서·희귀 오류 검증 부족, 표·차트·수식 등 혼합 콘텐츠 미지원, LLM 정성평가 편향 가능성, 오염 비율의 통계적 근거 부족을 열거한다(p. 7-8).

### 4. 우리 졸업과제와의 연관성

| 관점 | 판단 | 원문 근거와 프로젝트 해석 |
|---|---|---|
| OCR / 이미지 기반 추출 | 높음 | OCR 오류가 키 추출·NER·검색으로 전파될 수 있다고 분석한다. |
| LLM 비정형 데이터 구조화 | 보통 | OCR+LLM이 오류를 상속할 수 있음을 지적하고 구조화 OCR 출력을 DB/지식베이스에 쓰려 한다. JSON schema 평가는 없다. |
| 온디바이스-클라우드 역할 분리 | 해당 없음 | GPU 환경의 OCR 보정 연구이며 모바일·분할 처리를 다루지 않는다. |
| Precision / Recall / F1 | 보통 | Recall@K·CORD QA F1은 보고하나 OCR 문자·필드 추출 P/R/F1은 아니다. |
| 처리 속도 및 비용 | 해당 없음 | 지연시간·API 비용은 보고하지 않는다. |
| 구조화 저장 | 보통 | DB·지식베이스 활용 가능성을 제시하나 구체 스키마는 없다. |
| 모바일/온디바이스 | 해당 없음 | 모바일 실험이 없다. |
| 개인정보·보안 | 해당 없음 | 개인정보 탐지·마스킹·암호화 평가가 없다. |
| 확장 가능한 아키텍처 | 부분적 연관 | 다양한 오류를 다루려 하나 도메인·혼합 콘텐츠 한계를 명시한다. |

### 5. 최종보고서에서 사용할 수 있는 핵심 근거

1. **논문의 주장:** OCR 오류는 key extraction·NER·검색 등 후속 과업에 누적 전파될 수 있다. **원문 위치:** 3-3.1절, p. 3. **활용:** OCR 결과를 자동 확정하지 않고 검토·후속 처리 대상으로 두는 이유.
2. **논문의 주장:** 오류 taxonomy와 함께 REVISE meta는 검색 Recall 및 BERTScore·QA F1을 개선했다. **원문 위치:** 표 1, p. 3; 표 2-4, p. 5-6. **활용:** OCR 품질 관리가 후속 정보 활용과 연관될 수 있다는 실증 근거.
3. **논문의 주장:** 오류 유형·분포가 맞지 않으면 과교정으로 baseline보다 낮아질 수 있다. **원문 위치:** 5.1절, p. 6. **활용:** 자동 결과에 사용자 수정·승인 단계를 두고 실제 입력으로 평가할 필요성.

### 6. 최종보고서용 서술문

Shim, Hong, and Lim(2026)은 OCR의 문자 치환·삭제·삽입, 단어 분절, 다단 문서 읽기 순서 오류가 후속 정보추출과 검색·질의응답의 품질을 저해할 수 있음을 지적하고, 이를 문자·단어·구조 수준에서 교정하는 REVISE를 제안하였다[Shim et al., 2026]. 공개 문서 데이터에서 REVISE는 검색 Recall, BERTScore 및 일부 질의응답 지표를 개선하여 OCR 출력 품질과 후속 정보 활용 품질의 관련성을 보였다.

본 프로젝트에서는 OCR 텍스트가 구조화 필드 추출의 입력이므로, OCR 오류 가능성을 고려하여 추출 결과를 사용자 검토가 가능한 초안으로 취급한다. 다만 REVISE는 영어 공개 데이터의 검색·QA 연구이며, 한국어 모바일 스크린샷, JSON 필드 추출, 개인정보 보호를 직접 검증하지 않았으므로 이 요소들은 본 프로젝트의 자체 평가로 구분한다.

## 종합 시사점 및 아키텍처 설계 판단의 논리적 흐름

### A. 우리 프로젝트를 뒷받침하는 선행연구의 핵심 흐름

1. **입력 이해:** ScreenSeg와 Garg et al.은 모바일 스크린샷·문서가 텍스트만이 아니라 시각적 구조를 지닌 입력이며, 단말에서 이를 분석할 수 있음을 보인다.
2. **로컬 처리와 보호:** 이종한 등과 Garg et al.은 원문 전송에 따른 프라이버시·지연 문제를 배경으로, OCR·비식별화·분류의 일부를 클라이언트/단말에서 수행한다.
3. **선택적 LLM 활용:** 김호준 등은 실시간 판단은 단말 모델로, 후속 문맥 처리·리포트는 조건부 LLM/RAG로 나누는 사례를 제시한다.
4. **출력 품질과 운영:** Shim et al.은 OCR 오류가 후속 정보 활용에 영향을 줄 수 있음을, 정휘수 등은 다수 LLM 요청에서 자원·처리량 관리가 중요함을 제시한다.
5. **본 프로젝트의 설계:** 위 흐름을 바탕으로 소생 앱은 단말의 OCR·정형 패턴·1차 분류, 선택적 LLM의 비정형 필드 구조화, 사용자 검토 및 로컬 JSON 저장을 연결한다. 이 결합 자체와 그 성능은 본 프로젝트의 구현·실험 결과로 제시한다.

| 입력 | 근로계약서, 키패드 텍스트, 화면 레이아웃, PDF 문서, 공개 OCR 문서 | 사용자 스크린샷의 OCR 텍스트와 이미지 단서 |
| 1차 처리 | OCR·NER·레이아웃 분석·문서/문장 분류 | 단말 OCR, 정형 패턴 추출, 1차 분류, 민감정보 전처리 |
| LLM 역할 | 법률 분석, 문장 대치·리포트, OCR 보정, 온디바이스 추론 운영 | 비정형 필드 구조화 및 보강 |
| 데이터 관리 | JSON 응답, 서비스 ERD, DB/지식베이스 활용 가능성 등 | 로컬 SQLite와 가변 JSON 필드, 이미지 파일 매핑, 상태 관리 |
| 검증 | 각 논문 고유 과업의 정확도·F1·Recall·지연시간 | 스크린샷 필드 단위 Precision/Recall/F1 및 처리시간·비용의 자체 실험 |

차별점은 기존 연구보다 우수하다는 주장이 아니라, 서로 다른 선행연구의 문제의식을 스크린샷 관리 흐름에 맞게 통합했다는 데 있다.

### D. 실제 보고서에 인용하기 좋은 논문 TOP 3
