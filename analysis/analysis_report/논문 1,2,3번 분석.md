# 선행연구 분석 및 이론적 근거 도출 리포트

본 리포트는 졸업과제 최종보고서의 시스템 아키텍처 및 설계 근거를 뒷받침하기 위해 관련 선행연구를 분석한 내용입니다. 기존 연구의 한계 및 제안 방식을 바탕으로 본 프로젝트가 어떻게 설계 및 구현되었으며, 나아가 실제 실험 결과를 통해 해당 설계의 타당성을 어떻게 평가하였는지 서술합니다.

## [논문 1] 개인정보 보호형 LLM 기반 실시간 근로계약서 분석 및 가이드 시스템

### 1. 서지정보
- **저자:** 이종한, 박성재, 이채은, 권아현, 김민재, 신현석, 황연우, 서왕덕 (2026)
- **학회/저널:** 한국정보기술학회 하계 종합학술대회 논문집

### 2. 핵심 내용 요약
해당 연구는 근로계약서와 같이 민감한 개인정보가 다수 포함된 문서를 대규모 언어 모델(LLM)로 분석할 때 발생하는 보안 취약점을 다룹니다. 이를 해결하기 위해 모바일 단말(클라이언트)에서 OCR 기술을 활용해 텍스트를 우선 추출한 후, 고유명사 및 민감정보를 사전에 비식별화(마스킹)하여 서버로 전송하는 **클라이언트-서버 분리형 아키텍처**를 제안하였습니다. 특히, 민감정보를 단순히 삭제하는 대신 식별 가능한 라벨로 치환함으로써 원문의 문맥을 최대한 유지하면서 개인정보를 보호하는 방식을 구현하였습니다.

### 3. 최종보고서 활용 서술문
> 이종한 등(2026)은 모바일 클라이언트에서 OCR 및 개인정보 비식별화를 수행한 후 클라우드 서버의 LLM을 통해 문서를 분석하는 클라이언트-서버 구조를 제안하였다. 해당 선행연구에서는 민감정보를 삭제하는 대신 식별 가능한 라벨로 치환하여 문맥의 훼손을 방지하면서 개인정보 보호를 도모하는 방식을 채택하였다. 본 프로젝트 역시 영수증, 결제 내역 등 사용자의 민감 정보가 포함될 가능성이 높은 이미지 데이터를 다루고 있으므로, 해당 연구의 클라이언트 측 비식별화 구조를 참고하여 서버 전송 이전의 로컬(단말) 전처리 단계를 구성하였다. 이를 바탕으로 본 프로젝트에서는 자체적인 데이터 보호 방식으로서 `[ENC:...]` 심볼 치환을 적용한 `MaskingHelper` 모듈을 설계하였으며, 결과적으로 개인정보의 외부 전송을 최소화하는 개인정보 보호형 처리 아키텍처를 구현하였다.

## [논문 2] ScreenSeg: On-Device Screenshot Layout Analysis

### 1. 서지정보
- **저자:** Manoj Goyal, Rachit S Munjal, Sukumar Moharana, Deepak Garg, Debi Prasanna Mohanty, Siva Prasad Thota (2021)
- **학회/저널:** arXiv preprint arXiv:2104.08052

### 2. 핵심 내용 요약
이 논문은 모바일 기기 화면 캡처(Screenshot) 데이터를 분석함에 있어, 자원이 제한된 단말기 내부(On-Device)에서 실시간으로 레이아웃과 구성 요소(텍스트, 이미지, 아이콘 등)를 분할하고 파악할 수 있는 파이프라인을 제안합니다. 복잡한 구조를 가진 모바일 이미지를 처리하기 위해 딥러닝과 이미지 처리 기법을 결합하였으며, 모바일 환경에 맞춘 모델 경량화(Light-weight) 최적화를 통해 제한된 자원 위에서도 실시간 처리가 가능함을 보여주었습니다.

### 3. 최종보고서 활용 서술문
> 모바일 환경에서 이미지 분석을 수행하기 위해서는 단말의 제한된 컴퓨팅 자원과 실시간 처리 요구사항을 함께 고려할 필요가 있다. Goyal et al.(2021)은 이와 같이 컴퓨팅 자원이 제한적인 모바일 단말(On-Device) 환경에서 이미지를 분석하기 위해서는 경량화(Light-weight)된 처리 파이프라인이 필요함을 지적하였다. 본 프로젝트 또한 이러한 모바일 환경의 제약과 실시간 처리 요구사항을 고려하여 전체 분석 파이프라인의 역할을 분리하였다. 구체적으로, 고도의 문맥 이해가 요구되는 분석은 서버의 LLM으로 위임하되, 데이터의 1차적인 카테고리 식별 및 고정 패턴 탐지는 단말 환경에서 비교적 경량으로 수행할 수 있는 ML Kit OCR 및 정규표현식(Regex)을 통해 처리하도록 구성하여 불필요한 서버 연산을 줄이고 사용자 응답성을 높이고자 하였다.

## [논문 3] On-device LLM모델의 반응성 향상을 위한 동적 배치 최적화 기술 (보조 근거)

### 1. 서지정보
- **저자:** 정휘수, 이지훈, 주성진, 이길호 (2024)
- **학회/저널:** 한국소프트웨어종합학술대회 논문집

### 2. 핵심 내용 요약
해당 논문은 온디바이스 LLM 인퍼런스 환경을 대상으로, 입력 시퀀스의 길이가 불규칙할 때 발생하는 시스템 메모리(Out-Of-Memory) 문제와 성능 저하를 해결하고자 하였습니다. 입력 데이터의 길이, KV 캐시, GPU 메모리 등을 종합적으로 고려하여 배치를 유동적으로 구성하는 '동적 배치 최적화' 알고리즘을 제안하였습니다.

### 3. 최종보고서 활용 서술문
> LLM 기반 데이터 분석 시스템에서는 다수의 요청을 동시에 처리할 때 시스템의 가용 자원과 요청 특성을 고려한 처리량 관리가 필요하다. 정휘수 등(2024)은 온디바이스 LLM 환경에서 입력 시퀀스의 길이와 GPU 메모리, KV 캐시 등을 고려하여 배치를 동적으로 구성함으로써 처리 효율을 향상시키는 방법을 제안하였다. 본 프로젝트에서 적용한 세마포어(Semaphore=3) 기반 동시성 제어는 해당 연구의 동적 배치 알고리즘과는 구현 방식이 다르지만, 제한된 시스템 자원 내에서 다수의 LLM 요청을 안정적으로 처리하기 위해 처리량을 제어한다는 설계 목적을 공유한다. 이에 본 프로젝트에서는 한 번에 최대 20장의 이미지를 분석하는 상황을 고려하여, 외부 LLM API에 대한 동시 요청 증가에 대응하고 서버 측 처리 부하를 관리하기 위해 API 호출의 동시 실행 수를 제한하도록 설계하였다.

## 종합 시사점 및 아키텍처 설계 판단의 논리적 흐름

### A. 종합 시사점 (선행연구 통합 분석)
선행연구 분석을 통해 본 프로젝트의 이미지 정보 처리 아키텍처는 **모바일 환경의 자원 제약, 개인정보 보호, 서버 측 처리 부하**라는 세 가지 요구사항을 고려하여 설계되었음을 확인할 수 있다.

첫째, Goyal et al.(2021)의 ScreenSeg는 제한된 모바일 컴퓨팅 환경에서도 이미지 분석을 수행하기 위해 경량화된 온디바이스 처리 파이프라인이 필요함을 보여준다. 이를 바탕으로 본 프로젝트에서는 이미지의 1차적인 OCR 및 패턴 기반 정보 처리를 단말에서 수행하도록 설계하였다.

둘째, 이종한 등(2026)은 모바일 클라이언트에서 OCR 및 개인정보 비식별화를 수행한 후 서버의 LLM을 이용하는 클라이언트-서버 구조를 제안하였다. 이는 개인정보가 포함될 수 있는 이미지 데이터를 처리하는 본 프로젝트에서 서버 전송 이전의 로컬 전처리 단계를 구성하는 설계 근거로 활용하였다.

셋째, 정휘수 등(2024)은 LLM 추론 과정에서 시스템 자원과 입력 특성을 고려한 처리량 관리의 중요성을 제시하였다. 본 프로젝트에서는 이를 참고하여 다수의 이미지 분석 요청이 발생하는 상황에서 서버 측 LLM 호출의 동시 실행 수를 제한하는 방식으로 처리 부하를 관리하였다.

따라서 본 프로젝트의 전체 처리 구조는 모든 분석을 단일 처리 방식에 의존하기보다, **단말에서 효율적으로 수행할 수 있는 작업과 서버 LLM을 통해 수행해야 하는 작업을 구분**하는 방식으로 구성하였다. 이를 통해 모바일 환경에서의 처리 효율성, 개인정보 보호, 서버 처리 안정성을 함께 고려하는 하이브리드 정보 추출 구조를 구현하였다.

### B. 선행연구에서 설계, 그리고 실제 실험 결과로의 연결
보고서의 학술적 설득력을 높이기 위해 본 프로젝트의 구현 흐름을 선행연구, 설계 판단, 실제 구현 및 실험 결과의 순서로 연결할 수 있다.

#### 1) 온디바이스 처리 성능 최적화
- **선행연구 (ScreenSeg):** 모바일 환경에서는 제한된 자원을 고려한 경량화(Light-weight)된 온디바이스 이미지 처리 파이프라인이 필요하다.
- **설계 판단:** 서버 측 연산 의존도를 줄이기 위해 비교적 경량으로 수행할 수 있는 ML Kit OCR과 정규표현식(Regex)을 단말 환경의 1차 처리 과정으로 구성하였다.
- **실제 실험 결과:** Regex 추출은 건당 평균 0.17ms, LLM 추출은 건당 평균 1.32초 소요되었다.
- **아키텍처 결론:** 정형·고정 패턴 데이터에 대해서는 Regex가 LLM보다 현저히 낮은 지연 시간으로 처리할 수 있으며, 문맥적 해석이 필요한 비정형 엔티티 데이터는 LLM을 활용하는 방식이 효율적이다.

#### 2) 개인정보 보호
- **선행연구 (이종한 등):** 원본 데이터의 서버 전송을 최소화하기 위해 클라이언트 단에서 사전에 개인정보 비식별화를 수행한 뒤 서버 LLM으로 분석을 위임하는 구조가 제안되었다.
- **설계 판단:** 서버 통신 이전에 민감 정보를 선제적으로 치환하는 온디바이스 전처리 모듈(`MaskingHelper`)을 설계하였다.
- **실제 구현체:** OCR로 추출된 텍스트에서 민감 정보 패턴을 자체적으로 식별하여 `[ENC:...]` 특수 심볼로 치환한다.
- **아키텍처 결론:** 민감정보 원본을 외부 LLM API로 그대로 전달하지 않고 사전에 치환하는 처리 구조를 적용함으로써, 민감정보의 외부 전송을 최소화하도록 설계하였다. 이를 통해 LLM 기반 정보 추출 과정에서도 개인정보 보호를 고려할 수 있는 클라이언트-서버 처리 구조를 구현하였다.

#### 3) 서버 동시성 관리
- **선행연구 (정휘수 등):** 대량의 LLM 처리에서 시스템 자원과 입력 특성을 고려한 처리량 관리가 중요하다.
- **설계 판단:** 다수의 이미지 분석 요청 시 외부 LLM API에 대한 동시 요청 증가에 대응하기 위해 서버 측에서 동시 실행 수를 제한하는 로직을 도입하였다.
- **실제 구현체:** FastAPI 서버 단에서 스레드 풀과 세마포어(Semaphore=3)를 활용하여 동시 요청 수를 통제한다.
- **설계 적용 결과:** 다중 이미지 요청 시 LLM API 호출을 동시에 최대 3개로 제한하도록 구성하여, 한 번에 많은 요청이 발생하더라도 서버에서 처리되는 외부 API 호출량을 제어할 수 있도록 하였다.
