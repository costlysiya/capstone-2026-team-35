# 캡스톤 중간보고서 자문의견 반영 및 최종 종합 보고서

본 문서는 전문가 자문의견(Expert Feedback)을 바탕으로 새롭게 수행된 성능 평가 및 아키텍처 분석 결과를 종합하여, 피드백의 각 항목이 어떻게 충족되었는지 설명합니다.

---

## 1. 온디바이스 vs LLM 정보 추출 품질 및 성능 비교 (피드백 2번 충족)
새롭게 분석된 `OCR정확도 비교.md`와 `온디바이스_vs_llm_성능분석.md`를 통해, 온디바이스(Regex)와 LLM(GPT-4o-mini) 간의 추출 품질과 처리 성능을 정량적으로 증명했습니다.

*   **추출 정확도:** 정형 데이터(날짜 등)는 온디바이스도 준수한 성능(66.7%)을 내지만, 비정형 데이터(장소명, 상호명 등)에서는 LLM이 압도적인 우위(80.6% 이상)를 보입니다. 전체 필드 평균 추출 정확도는 **온디바이스 38.6% vs LLM 84.1%** 로 LLM이 2.2배 높습니다.
*   **처리 속도 및 비용:** 온디바이스 방식은 건당 0.135ms 이하로 거의 즉시 처리되나, LLM은 약 1~2.7초의 지연이 발생합니다. LLM 비용은 건당 약 0.3원(월 90원 수준)으로 투자 대비 효용(ROI)이 뛰어납니다.
*   **결론 (2단계 하이브리드 아키텍처 정당성):** 분류는 온디바이스에서 즉시 처리하고, 상세 정보 추출은 LLM에 위임하는 현재의 하이브리드 구조가 속도, 정확도, 비용 효율성을 모두 잡은 최적의 아키텍처임을 논리적으로 증명했습니다.

## 2. 개인정보(민감정보) 탐지 고도화 및 테스트 (피드백 4번 충족)
`민감정보추출 테스트.md`를 통해 E2EE 파이프라인의 개인정보 보호 메커니즘을 상세히 검증했습니다.

*   **하이브리드 매칭 도입:** 기존 단순 정규식의 한계를 극복하기 위해 키워드 기반 교차 검증을 추가하여 오탐지(False Positive)를 획기적으로 줄였습니다.
*   **프롬프트 최적화:** LLM이 암호문(`[ENC:...]`)을 무시하지 않고 반환하도록 시스템 프롬프트를 튜닝하여 제로 데이터 유출(Zero Data Leakage)을 완벽히 구현했습니다.
*   **NER 모델 탑재를 통한 이중 방어막 구축 (고도화 완료):** 단순히 향후 과제로 남겨두지 않고, 온디바이스 기반 초경량 NER 모델을 전면 도입 완료했습니다. 텍스트 전체를 NER 모델에 통과시켜 문맥 기반으로 개인정보를 1차로 가리고, 정규식(Regex)으로 2차로 완벽하게 덮는 '이중 방어막' 체계를 구축하여 오탐과 누락을 원천 차단했습니다.

## 3. 데이터베이스(DB) 및 확장성 아키텍처 정리 (피드백 5번 충족)
`데이터베이스_및_확장성_아키텍처_정리.md`를 통해 앱의 내부 저장소 관리 최적화 전략을 입증했습니다.

*   **동적 JSON 스키마 적용:** 카테고리별로 각기 다른 메타데이터를 수용하기 위해 SQLite의 `fields` 컬럼에 JSON 구조를 채택하여 DB 확장성을 극대화했습니다.
*   **용량 최적화 스마트 스토리지 전략:** 사용자 스마트폰 갤러리의 용량 부족 문제를 해결하기 위해, 기프티콘이나 위시리스트 등 사진 원본이 필요한 항목만 내부 저장소에 복사하고, 단순 일정이나 장소 정보는 텍스트만 추출한 뒤 원본 사진을 파기/삭제하여 효율적인 용량 관리를 실현했습니다.

## 4. 실제 사용자 경험(UX) 중심의 시나리오 구성 (피드백 3번 충족)
각 문서의 분석 결과를 통해, 단순한 기능 나열을 넘어 **실제 사용자의 불편함(용량 부족, 정보 입력의 번거로움)을 어떻게 기술적으로 해소했는지** 명확한 흐름도로 시각화되었습니다. 갤러리 이미지 일괄 삭제 흐름, 하이브리드 속도(분류 1ms 이하)를 통한 사용자 대기 시간 최소화 등 UX 개선 효과가 돋보입니다.
