# OCR 정보 추출(Extraction) 품질 평가 보고서

## 1. 실험 개요

본 실험은 '소생 앱'에서 사용자가 입력한 스크린샷의 OCR 텍스트로부터 **날짜, 가격, 장소명** 등 주요 정보가 얼마나 정확하게 추출되는지를 정량적으로 측정하고, **LLM 분석을 병행했을 때 실제로 얼마나 개선되는지**를 비교 평가한 것입니다.

> [!NOTE]
> 카테고리 분류는 사용자가 직접 선택하므로 본 평가에서는 제외하고, **추출(Extraction) 품질에만 집중**합니다.

### 1.1 실험 설계

| 항목 | 내용 |
|:---|:---|
| **평가 대상 데이터** | 실제 앱 사용 데이터(`dataset.csv`)에서 카테고리별 50개씩, **총 200개** 무작위 샘플 |
| **정답지(Ground Truth)** | GPT-4o 모델이 동일 OCR 텍스트를 분석하여 생성한 기준값 |
| **비교 방식 A** | **온디바이스(Regex)** — 정규표현식 기반 패턴 매칭으로 정보 추출 (서버 불필요) |
| **비교 방식 B** | **LLM(GPT-4o-mini)** — 앱 서버에서 사용하는 것과 동일한 프롬프트로 정보 추출 |
| **평가 기준** | 정답지 대비 날짜·가격·장소명 등의 매칭 정확도 (부분 매칭 허용) |

### 1.2 카테고리별 주요 추출 대상

| 카테고리 | 주요 추출 필드 |
|:---|:---|
| **SCHEDULE** (일정) | 날짜(시작일/종료일), 가격, 장소명 |
| **PLACE** (장소) | 상호명, 지역/주소, 평점, 가격대 |
| **WISHLIST** (위시리스트) | 상품명, 가격, 브랜드 |
| **MEMO** (메모) | 날짜, 제목/핵심 요약 |

## 2. 실험 결과

### 2.1 SCHEDULE (일정) — N=50

| 추출 항목 | 온디바이스(Regex) | LLM(GPT-4o-mini) | 분석 |
|:---|:---|:---|:---|
| **날짜** | **66.7%** (30/45) | 33.3% (15/45) | Regex가 2배 우세. 정형화된 날짜 패턴(`2026.06.28`, `2026년6월24일`)은 Regex가 직접 매칭하므로 높은 정확도를 보임. 반면 LLM은 '취소마감일시 배제' 등 엄격한 프롬프트 제약으로 보수적 추출. |
| **가격** | 71.4% (10/14) | **85.7%** (12/14) | LLM이 우세. OCR 오인식된 가격 문자열도 문맥을 통해 교정하여 추출. |
| **장소** | 9.5% (4/42) | **66.7%** (28/42) | LLM이 압도적 우세. Regex는 '장소:'와 같은 명시적 키워드가 없으면 추출 불가. LLM은 문맥에서 장소를 유추하여 추출. |

> [!IMPORTANT]
> 일정(SCHEDULE) 카테고리에서 날짜는 Regex가 더 정확하지만, 장소명 추출은 LLM이 **7배 이상** 높은 정확도를 보여 **하이브리드 방식이 최적**임을 시사합니다.

## 4. 종합 분석 및 결론

### 4.1 Regex vs LLM: 항목별 우위 정리

```
┌──────────────────┬───────────────────────┬───────────────────────┐
│     추출 항목     │   온디바이스(Regex)    │    LLM(GPT-4o-mini)   │
├──────────────────┼───────────────────────┼───────────────────────┤
│ 정형 날짜         │ ✅ 우세 (66.7%)       │ 열세 (33.3%)          │
│ 정형 가격 (쇼핑)  │ 준수 (87.8%)          │ ✅ 소폭 우세 (95.9%)   │
│ 장소명 / 상호명   │ ❌ 매우 약함 (5~9%)    │ ✅ 압도적 (67~81%)     │
│ 지역/주소         │ ❌ 불가               │ ✅ 우수 (89.7%)        │
│ 상품명            │ ❌ 불가               │ ✅ 가능 (64.3%)        │
│ 평점              │ ❌ 불가               │ ✅ 우수 (88.2%)        │
│ 제목/요약         │ ❌ 불가               │ ✅ 가능 (47.9%)        │
├──────────────────┼───────────────────────┼───────────────────────┤
│ 처리 속도         │ ✅ 0.135 ms           │ 1.06 s                │
│ 비용              │ ✅ 무료               │ 약 0.3원/건            │
└──────────────────┴───────────────────────┴───────────────────────┘
```

### 4.2 핵심 인사이트

1. **정형 데이터(날짜, 가격)는 온디바이스(Regex)가 더 빠르고 정확합니다.**
   - 날짜 패턴(`YYYY-MM-DD`, `YYYY년M월D일`)과 가격 패턴(`000,000원`)은 정규표현식으로 즉시 추출 가능하며, LLM보다 약 **7,850배 빠른** 처리 속도를 보입니다.

2. **비정형 데이터(장소명, 상품명, 요약)는 LLM이 압도적으로 우수합니다.**
   - 상호명 추출: Regex **5.6%** → LLM **80.6%** (약 14배 개선)
   - 장소 추출: Regex **9.5%** → LLM **66.7%** (약 7배 개선)
   - 이는 Regex가 근본적으로 수행할 수 없는 **의미 기반 추출(Semantic Extraction)**을 LLM이 담당하기 때문입니다.

3. **현재 소생 앱의 하이브리드 아키텍처는 최적의 설계입니다.**
   - 1차: 온디바이스에서 Regex로 날짜·가격 등 정형 정보를 **즉시(0.1ms)** 추출하여 UI에 오토필
   - 2차: LLM 서버에 비동기 요청하여 장소명·상품명·요약 등 비정형 정보를 **1초 내에** 보강
   - 이를 통해 **속도와 정확도, 비용 효율성을 모두 달성**하는 구조입니다.

### 4.3 비용 대비 효과 (ROI)

| 시나리오 | 월 예상 비용 | 추출 가능 정보 |
|:---|:---|:---|
| Regex만 사용 | **무료** | 날짜, 가격 (한정적) |
| LLM만 사용 | 약 90원/월 (일 10건 기준) | 날짜, 가격, 장소, 상품명, 요약 등 전체 |
| **하이브리드 (현재 구조)** | 약 90원/월 | 날짜·가격은 즉시 표시 + 장소·상품·요약은 1초 후 보강 |

> [!IMPORTANT]
> LLM을 병행함으로써 **월 90원의 초저비용**으로 장소명 추출 정확도를 9.5%에서 66.7%로, 상호명 추출을 5.6%에서 80.6%로 끌어올릴 수 있어, 투자 대비 효용(ROI)이 매우 높습니다.
