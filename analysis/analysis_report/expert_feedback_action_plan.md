# 캡스톤디자인 중간보고서 전문가 자문 피드백 조치 계획

> [!TIP]
> **전문가 총평 요약**
> 온디바이스(로컬) + 선택적 서버(LLM)의 2단계 구조와 개인정보 보호, 비용/속도 절감 측면에서 우수한 평가를 받았습니다. 
> 향후 과제는 '새로운 기능 추가'보다는 **현재 구조의 효율성과 실제 사용자 편의성 향상 효과를 명확한 수치와 사례로 증명**하는 데 집중해야 합니다.

## 1. 카테고리별 분류 성능 세분화 및 시각화 (Confusion Matrix)
> [!IMPORTANT]
> 특정 카테고리(예: 메모) 데이터 편향에 따른 전체 정확도 왜곡 현상을 방지하고, 세부 성능을 투명하게 공개해야 합니다.

* **현황 및 문제점:** 전체 정확도는 96%로 높으나, 다수 데이터 클래스의 영향일 수 있음.
* **조치 계획 (Action Item):**
  * 검증(Validation) 단계에서 카테고리별 Precision, Recall 측정 로직 추가
  * Confusion Matrix(혼동 행렬)를 생성하여 클래스 간 오분류 양상 시각화 및 분석 보고서 추가

## 2. 온디바이스 vs LLM 정보 추출 품질 및 성능 비교
> [!NOTE]
> 단순 분류를 넘어 텍스트(정보) 추출 품질 자체를 평가하고, 우리의 2단계 구조 설계가 합리적인 이유를 비용/시간 측면에서 증명해야 합니다.

* **현황 및 문제점:** 정보 추출 품질에 대한 정량적 비교 자료가 부족함.
* **조치 계획 (Action Item):**
  * 10~20개의 테스트 데이터 셋 구축
  * **비교군 1:** 온디바이스 (OCR + 분류) 단독 처리 결과
  * **비교군 2:** LLM 분석 처리 결과
  * 두 방식 간의 추출 정확도(날짜, 가격, 장소명 등) 및 처리 소요 시간 측정 후 표(Table) 형태로 정리

## 3. 실제 사용자 경험(UX) 중심의 시나리오 구성
* **현황 및 문제점:** 기능 구현 여부에 초점이 맞춰져 있어, 최종 사용자의 실질적인 편의성 개선 효과가 와닿지 않음.
* **조치 계획 (Action Item):**
  * 핵심 사용 사례 3가지 도출: 기프티콘 만료일 관리, 영수증 기반 장소 확인, 캘린더 일정 등록
  * 사용자 흐름도 시각화: `원본 이미지 → 로컬 OCR 및 분류 → 사용자 검토 → LLM 심층 분석 → 최종 저장`
  * 오류 복구 사례(분류 실패 시 사용자의 수동 개입 및 수정)를 포함하여 앱의 실사용 모습 시현

## 4. 개인정보(민감정보) 탐지 고도화 및 테스트
> [!WARNING]
> 현재의 정규식 기반 탐지로는 변형된 형태의 개인정보를 놓칠 위험이 있으므로, 더 촘촘한 보안 로직 테스트가 필요합니다.

* **현황 및 문제점:** 기본적인 정규표현식으로만 필터링 중이며, 바코드나 변형된 주민/카드번호 탐지 기능이 미흡할 수 있음.
* **조치 계획 (Action Item):**
  * 하이픈(-) 유무, 공백 유무 등 다양한 패턴을 지원하도록 정규표현식(Regex) 강화
  * 가상 개인정보를 포함한 더미(Dummy) 이미지를 활용하여 탐지 누락(False Negative) 테스트 수행 및 결과 문서화

## 5. 데이터베이스(DB) 및 확장성 아키텍처 정리
* **현황 및 문제점:** 데이터 누적 시 이미지 원본과 구조화된 데이터를 어떻게 저장하고 관리할 것인지에 대한 설계 명세서가 부족함.
* **조치 계획 (Action Item):**
  * 로컬 DB (동적 Key-Value 구조) 스키마 문서화
  * 파일 스토리지 구조도 작성 (원본 이미지의 앱 내부 저장 경로 및 DB와의 맵핑 관계 명시)
