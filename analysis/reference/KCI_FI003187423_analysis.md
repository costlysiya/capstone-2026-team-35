## 2. 연구 목적 및 문제 정의

### 해결하려는 문제

청소년이 일상적으로 사용하는 모바일 메시지 환경에서 비속어 및 사이버 폭력이 확산되고 있으며, 기존의 단순 키워드 필터링 방식은 문맥을 고려하지 못해 오탐(false positive) 및 미탐(false negative) 문제가 발생한다. 또한 부모가 자녀의 언어 습관을 파악하는 과정에서 자녀의 사생활이 침해될 위험이 존재한다.

### 연구의 주요 목적

본 논문은 LLM 기반 분류 모델과 RAG(Retrieval-Augmented Generation)를 결합하여 청소년의 비속어를 실시간으로 감지하고 상황에 적합한 대체 표현 또는 이모티콘을 제공하는 "바른말ㅆ.미" 서비스를 설계·구현하는 것을 목적으로 한다. 이 서비스는 키패드 모듈과 앱 모듈로 구성되며, 온디바이스 ML 모델과 서버 측 LLM을 각각의 역할에 맞게 분리·배치하는 아키텍처를 채택하였다. 특히 자녀의 실제 대화 원문 전체를 부모에게 노출하지 않고 요약·분석된 정보만을 전달함으로써 프라이버시를 보호하는 설계를 핵심 목표로 삼는다.

## 3. 핵심 내용

### 3-1. 연구 방법

본 논문의 연구 방법은 시스템 설계 및 구현 논문(Design & Implementation paper)의 형태를 취하며, 다음 두 가지 핵심 기술 구성 요소를 중심으로 서술된다.

1. **온디바이스 분류 모델**: 키패드에서 비속어를 실시간으로 감지하기 위해 `KoSim-CSE-BERT-multitask` 모델을 온디바이스(On-device)에서 실행한다. 사용자 입력 텍스트가 외부 서버로 전송되지 않도록 하여 데이터 노출 위험을 제거하는 프라이버시 중심 설계이다.

2. **LLM + RAG 기반 리포트 생성**: 누적된 텍스트 데이터는 서버 측 LLM으로 전달되어 언어 습관 및 사이버 폭력 관련 리포트를 자동 생성한다. RAG를 활용하여 도메인 지식을 보강하고, 리포트에는 실제 대화 내용의 일부만을 포함함으로써 자녀의 사생활을 보호한다.

### 3-2. 사용한 기술 및 환경

| 구성요소 | 기술 |
|----------|------|
| 온디바이스 분류 | KoSim-CSE-BERT-multitask 모델 |
| 서버 측 분석 | LLM (대형 언어 모델) |
| 지식 보강 | RAG (Retrieval-Augmented Generation) |
| 플랫폼 | 모바일 앱 + 커스텀 키패드 |

### 3-3. 핵심 실험 결과

> ⚠️ **주의**: 공개 초록에서는 구체적인 수치 성능 결과(Precision, Recall, F1 등)가 제시되지 않았습니다. 논문 본문 내의 실험 결과를 최종 보고서에 인용하려면 반드시 원문을 직접 확인하여 실제 수치를 검증하시기 바랍니다. 초록에서는 "온디바이스에서 데이터 노출 없이 빠르고 정확한 결과를 낸다"는 서술적 표현만 확인됩니다.

### 3-4. 연구에서 도출한 결론

- 온디바이스 BERT 계열 모델을 활용하면 외부 서버로의 데이터 전송 없이 실시간 분류가 가능하다.
- LLM과 RAG의 조합은 도메인 특화 분석 리포트를 자동 생성하는 데 효과적이다.
- 개인정보를 직접 노출하지 않고 AI 분석 결과만을 제공하는 방식이 프라이버시 보호 측면에서 유효하다.
- 온디바이스 처리와 클라우드 LLM 처리를 역할에 따라 분리하는 하이브리드 아키텍처가 실용적이다.

## 4. 우리 졸업과제와의 연관성

### 4-1. OCR / 이미지 기반 정보 추출
**해당 없음.** 본 논문은 텍스트 입력(키보드 타이핑) 기반 처리를 다루며, 이미지에서 텍스트를 추출하는 OCR 과정을 포함하지 않는다.

### 4-2. LLM을 활용한 비정형 데이터 구조화
**연관성 있음.** 본 논문은 비정형 텍스트(대화)를 LLM으로 분석하여 언어 습관 리포트라는 구조화된 정보로 변환하는 방법을 다룬다. 이는 본 프로젝트에서 OCR로 추출한 비정형 텍스트를 LLM으로 분류하고 구조화된 필드(일정, 장소, 위시리스트 등)로 변환하는 파이프라인과 개념적으로 유사한 접근 방식이다.

### 4-3. 온디바이스 처리와 클라우드/LLM 처리의 역할 분리
**연관성 높음.**

본 논문이 제안하는 아키텍처의 핵심:
- **온디바이스**: BERT 계열 경량 모델 → 실시간 처리, 프라이버시 보호
- **클라우드 LLM**: 누적 데이터 분석, 리포트 생성

본 프로젝트(Sortie 앱)에서 채택한 구조:
- **온디바이스**: NER(Named Entity Recognition) 기반 규칙 분류기, 온디바이스 TFLite BERT 모델 → OCR 후 1차 분류 및 민감정보 마스킹
- **클라우드 LLM**: OpenAI GPT 기반 서버 → 상세 필드 추출 및 구조화

이 역할 분리 설계를 뒷받침하는 선행연구로서 유의미하게 인용할 수 있다.

### 4-4. 정확도 / Precision / Recall / F1
**해당 없음 (주의 필요).** 공개 초록에서는 구체적인 수치가 제공되지 않으며, 단지 "빠르고 정확한 결과"라는 서술적 표현만 존재한다. 원문 논문에 수치가 있다면 인용 가능하나, 현재 확인된 정보만으로는 수치를 인용할 수 없다.

### 4-5. 처리 속도 및 비용
**부분적 연관성 있음.** 본 논문은 온디바이스 모델이 서버 호출 없이 "빠른" 결과를 낸다고 언급한다. 본 프로젝트에서도 온디바이스 1차 분류를 통해 서버 호출 횟수를 줄이는 설계를 도입하였으며, 이를 뒷받침하는 근거로 활용할 수 있다.

### 4-6. 구조화된 데이터 저장
**부분적 연관성 있음.** LLM 분석 결과를 구조화된 형태로 저장·전달하는 방식을 다루나, 본 프로젝트의 SQLite 기반 카드 저장 방식과는 구조적으로 다르다.

### 4-7. 모바일/온디바이스 환경
**연관성 높음.** 본 논문은 모바일 앱 및 커스텀 키패드를 플랫폼으로 채택하고, 온디바이스 ML 모델을 모바일 기기에서 직접 실행하는 환경을 다룬다. 본 프로젝트 역시 Flutter 기반 모바일 앱에서 TFLite 모델을 온디바이스 실행하는 구조를 채택하였다.

### 4-8. 개인정보 및 데이터 보안
**연관성 높음.** 본 논문의 핵심 설계 원칙 중 하나는 사용자의 실제 텍스트 데이터를 외부 서버로 직접 전송하지 않고, 온디바이스에서 처리하거나 분석된 결과만을 전달하는 것이다. 본 프로젝트에서도 OCR 텍스트 내 개인정보(이름, 전화번호, 카드번호 등)를 로컬에서 마스킹(E2EE 암호화)한 뒤 서버로 전송하는 방식을 구현하였다.

### 4-9. 확장 가능한 아키텍처
**부분적 연관성 있음.** 키패드와 앱의 이중 구조, 온디바이스-클라우드 역할 분리는 기능을 독립적으로 확장 가능하게 설계한 사례이다. 그러나 확장 가능성 자체를 논문에서 직접 주장하는 것인지는 원문 확인이 필요하다.

## 6. 최종보고서용 서술문

### 서술문 1 — 아키텍처 설계 근거 (온디바이스-클라우드 역할 분리)

모바일 환경에서 AI 기반 텍스트 분석 시스템을 설계할 때, 온디바이스 경량 모델과 클라우드 기반 대형 언어 모델(LLM)의 역할을 어떻게 분리하느냐는 성능, 비용, 프라이버시 보호 측면 모두에 영향을 미치는 핵심 설계 결정이다. 김호준 외(2025)는 청소년 비속어 예방 서비스 "바른말ㅆ.미"를 설계하면서, 실시간 비속어 분류에는 온디바이스에서 동작하는 경량 BERT 계열 모델(KoSim-CSE-BERT-multitask)을, 누적 데이터 기반의 심층 분석 및 리포트 생성에는 서버 측 LLM과 RAG를 각각 배치하는 하이브리드 아키텍처를 채택하였다 [김호준 외, 2025]. 이와 같이 처리 특성과 프라이버시 요구 수준에 따라 온디바이스와 클라우드 구성 요소를 분리하는 방식은, 양측의 장점을 실용적으로 결합한 설계 사례로 평가할 수 있다. 본 프로젝트(Sortie)에서도 이러한 설계 원칙을 참고하여, 스크린샷 이미지에서 추출된 텍스트에 대한 1차 분류를 온디바이스 TFLite 모델로 수행하고, 세부 필드 추출 및 구조화 작업은 서버 측 LLM에 위임하는 방식으로 구현하였다.

### 서술문 2 — 개인정보 보호 설계 근거

AI 기반 텍스트 분석 서비스에서 사용자 데이터를 외부 서버로 전송하는 것은 개인정보 유출 위험을 수반한다. 김호준 외(2025)는 이 문제에 대응하기 위해, 민감한 텍스트 처리를 온디바이스에서 완결하고 서버에는 분석 결과만을 전달하는 방식을 채택하였다. 논문의 초록에서는 "키패드에 사용한 KoSim-CSE-BERT-multitask 모델은 온디바이스에서 데이터 노출 없이 빠르고 정확한 결과를 낸다"고 명시하고 있다 [김호준 외, 2025]. 본 프로젝트에서도 OCR 텍스트 내 포함된 개인정보(이름, 전화번호, 계좌번호, 기프티콘 쿠폰 번호 등)를 서버 전송 전 로컬에서 정규식 및 NER 기반으로 감지하고 AES 암호화를 통해 마스킹하는 방식을 구현하였다. 이는 선행연구에서 확인된 온디바이스 처리의 프라이버시 보호 효과를 본 프로젝트의 데이터 보안 설계에 적용한 것이라 볼 수 있다.

## 8. 최종 평가

| 평가 항목 | 평가 |
|-----------|------|
| **우리 프로젝트와의 직접적인 연관성** | 보통~높음 |
| **최종보고서 참고문헌으로서의 적합성** | 높음 |

### 실제 인용하기 좋은 부분

1. **온디바이스 vs. 클라우드 역할 분리 아키텍처의 설계 근거** — 두 처리 방식의 역할 분리 필요성을 선행연구로 뒷받침하기에 적합하다.
2. **모바일 환경에서의 개인정보 보호 설계 원칙** — 서버 전송 전 온디바이스 처리를 통한 프라이버시 보호의 근거로 적합하다.
3. **LLM을 활용한 비정형 텍스트의 자동 구조화 가능성** — LLM 기반 정보 추출의 타당성 근거로 활용 가능하다.

### 주의해서 인용해야 하는 부분

- **수치 성능 데이터**: 공개 초록에는 구체적인 수치가 없다. 수치 인용 시 원문에서 직접 확인이 필요하다.
- **도메인 차이**: 본 논문의 핵심 도메인은 '비속어 감지'이고 본 프로젝트는 '스크린샷 정보 추출'이다. 기술적 접근 방식(온디바이스 + LLM)의 유사성을 인용하는 것은 적절하나, 해결 문제 자체가 동일하다는 표현은 삼가야 한다.
- **RAG 관련 인용**: 본 프로젝트는 RAG를 구현하지 않았으므로, RAG 관련 내용을 "유사하게 구현하였다"고 표현할 때는 연구자 해석임을 명확히 해야 한다.

## 종합 정리

### A. 우리 프로젝트를 뒷받침하는 선행연구의 핵심 흐름

본 논문(김호준 외, 2025)은 모바일 환경에서 민감 텍스트를 다루는 AI 서비스를 설계할 때, **온디바이스 경량 모델과 서버 LLM의 역할 분리**가 실용적으로 유효한 아키텍처임을 보여주는 국내 구현 사례이다. 이는 본 프로젝트(Sortie)의 핵심 아키텍처 원칙—1차 온디바이스 분류 → 2차 서버 LLM 상세 추출—을 지지하는 선행연구로 기능할 수 있다.

### B. 기존 연구와 우리 프로젝트의 차별점

| 항목 | 김호준 외 (2025) | 본 프로젝트 (Sortie) |
